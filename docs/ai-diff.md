# AI增加版

比对先在浏览器 Worker 中运行 structured-v3。默认比较标点；可选择忽略普通标点，金额、小数点、百分号及正负号始终保留。算法结果发布后，后台以 `gpt-6-luna`、`reasoning.effort=medium` 异步补充。算法结果不被 AI 删除或覆盖。

## 流程与边界

- `POST /api/ai-diff` 只接受已完成、同租户的文档 ID、比对选项及算法候选引文。服务端从已保存的规范化结果构造文本，绑定实际 PDF 哈希、解析结果签名及内容哈希。
- 每个文本单元拥有包含文档、页码、块号及单元序号的稳定 ID；AI 仅引用 ID 和原文，不生成坐标。原文校验只忽略空白，保留标点与大小写。重复匹配保留候选，不猜测位置。
- `GET /api/ai-diff/:id` 轮询状态。任务按租户和用户隔离，限制并发与保留数量，缓存绑定完整输入及模型配置。切换文档、取消或重新比对后，浏览器丢弃旧任务结果。
- 文字差异与格式差异分别计数。两个 DOCX 可以直接复核原生加粗、斜体、下划线、删除线等样式；扫描件的格式须另行视觉复核，不能因文字为零就显示“完全相同”。
- AI 服务不可用、超时、拒绝、截断或引文错误都不影响已发布的算法结果；界面明确显示完成、部分完成或不可用。

## 展示

算法与 AI 识别项分别呈现。AI 项展示双侧引文、改字、解释及定位状态，并关联引文范围内的算法识别项。关联不表示已验证算法覆盖了该项的所有变化。定位优先使用真实字符框，其次使用原有 span/行/区域框；不按字符数均分坐标。重复引文提供候选位置选择；缺少对应原文的一侧不画框。两侧按各自页码独立跳转。格式框绘制在正文外围，避免遮挡下划线。

原生格式复核仅检查两个 Word 中可以唯一配对且文字一致的段落的加粗、斜体、下划线、删除线、双删除线及字号。重复段落、文字已修改的段落和版式需视觉复核。`POST /api/ai-diff/:id/visual` 异步复核用户选定的对应页，所用图片由浏览器从当前加载的原件 PDF 渲染；仅引用这两页的原文单元。复核一页不能代表整份文档格式相同。扫描件缺少字符框时继续使用真实区域框，后续可对接提供字符坐标的细粒度 OCR。

## 配置

密钥只留在服务端，通过 `OPENAI_API_KEY` 环境变量注入（优先于 `ai_diff.api_key`），禁止放入 Vite 环境或浏览器。默认模型 `gpt-6-luna`、推理强度 `medium`。配置缺失时自动回到算法结果。任务为有界内存缓存，服务重启后可重新发起。

发布先更新算法及标点开关，再发布 AI API 和界面。保留部署前镜像、配置与静态资源以便回退。
