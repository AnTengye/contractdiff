段落排序问题诊断

问题描述

第3页的内容出现在了最后，而不是按照页码顺序显示

期望顺序: 第1页 → 第2页 → 第3页 → 第4页 → ...

实际顺序: 第1页 → 第2页 → 第4页 → ... → 第3页（最后）

诊断步骤

请在浏览器控制台运行以下命令：

1. 检查原始数据顺序

可能的原因

  1. 后端数据顺序错误 - paragraphs 数组本身就是乱序的
  2. 块对齐算法问题 - unmatched 块被添加到最后
  3. 排序逻辑失效 - blockAlignment.ts 第 139-144 行的排序没有生效
  4. 渲染顺序问题 - DiffPaneV2 按照 diffs 数组顺序渲染，但 diffs 顺序不对

预期的排序逻辑

在 blockAlignment.ts 第 139-144 行：

// Sort alignments by position (left first, then right)
alignments.sort((a, b) => {
  const aPos = a.leftIndex !== null ? a.leftIndex : 1000000 + (a.rightIndex || 0);
  const bPos = b.leftIndex !== null ? b.leftIndex : 1000000 + (b.rightIndex || 0);
  return aPos - bPos;
});

逻辑解释：

  • 如果有 leftIndex，使用 leftIndex 作为排序位置
  • 如果没有 leftIndex（右侧新增），使用 1000000 + rightIndex
  • 这样左侧的块会按照原始顺序排在前面，右侧新增的排在后面

⚠️ 这个逻辑可能导致问题：右侧新增的块全部排到最后！

问题根源分析

如果第3页的段落是"右侧新增"（leftIndex = null），它会被排到 1000000+ 的位置，出现在最后！

示例：

对齐 leftIndex rightIndex 计算的 pos 排序后位置
第1页段落 0 0 0 1
第2页段落 1 1 1 2
第3页段落 null 4 1000004 最后！
第4页段落 2 5 2 3

解决方案

需要改进排序逻辑，使用页码和块索引进行排序，而不是基于对齐索引

建议的新排序逻辑：

// 使用页码和块索引排序
alignments.sort((a, b) => {
  const getBlockInfo = (alignment, blocks, side) => {
    const idx = side === 'left' ? alignment.leftIndex : alignment.rightIndex;
    if (idx === null) return null;
    const block = blocks[idx];
    return { pageIdx: block.pageIdx, index: block.index };
  };
  
  const aLeft = getBlockInfo(a, leftBlocks, 'left');
  const aRight = getBlockInfo(a, rightBlocks, 'right');
  const bLeft = getBlockInfo(b, leftBlocks, 'left');
  const bRight = getBlockInfo(b, rightBlocks, 'right');
  
  // 优先使用左侧的页码和索引
  const aInfo = aLeft || aRight;
  const bInfo = bLeft || bRight;
  
  if (!aInfo || !bInfo) return 0;
  
  // 先按页码排序，再按索引排序
  if (aInfo.pageIdx !== bInfo.pageIdx) {
    return aInfo.pageIdx - bInfo.pageIdx;
  }
  return aInfo.index - bInfo.index;
});
